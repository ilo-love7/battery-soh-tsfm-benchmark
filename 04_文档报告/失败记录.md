# 失败记录：本项目走不通的路

> 汇总截至 2026-10-22。每条写清三件事：为什么看起来有希望、证据是什么、结论是结构性的还是参数性的。
> 目的是让后来者不必重跑，也让「哪些前提必须改」有据可查。
> 详细数据在各自的分报告里，本文只放结论与关键数字。

## 1. §9.4 起点 × 上下文全因子 —— 结构性不可行

**想解决什么**：主表统一把上下文夹到 512，想知道 1024 / 2048 / 不截断会不会改变结论。

**证据**（`diag_context_range.py`，零推理）：183 个「cell × 起点」组合里，上下文 **>2048 的有 0 个**，>1024 的只有 6 个，最长 **1340**（MIT@0.6）。三个库的单支循环数中位：MIT 600、NASA 167、CALCE 694–805。

**结论**：2048 列是空操作、1024 列几乎空操作，因子退化成「512 vs 原生」，而后者在起点 0.5 已经做过。要长上下文成立需要单支电池 4000+ 循环 —— 公开库里没有。详见 `上下文范围.md`。

## 2. §9.5-a 用上下文特征回归在线估 `w` —— 只能估量级

**想解决什么**：区间系统性偏窄（PICP 2–22%），希望部署时不带真值也能把宽度估出来。

**证据**（`online_proxy.py`，留一库口径）：最强特征是 `n_ctx`（序列长度），13/15 次选中它 —— 模型学到的是「horizon 越长区间要越宽」这条协议常识，不是「这条序列的误差有多大」。覆盖率偏离从 42pp 压到 19pp，仅 3/15 进 ±10pp。

**结论**：`w` 不是上下文特征的函数，估不出可用值。19pp 是这三条路里最好的结果，也是后续对照的基准线。

## 3. §9.5-b conformal 上下文内自测 —— 测到的是「horizon 被截短」

**想解决什么**：绕开特征，在上下文内部做伪任务（前段输入、后段当真值），对齐「同一个模型、同一条序列、同一种误差结构」。理论上是这组尝试里最有希望的一条。

**证据**（`conformal_w.py`，118 个 cell）：

| 方案 | 需要真值？ | 覆盖率偏离 |
|---|---|---|
| 不校准 `w=1` | 否 | 65pp |
| 自测 `w_hat` | 否 | **38pp**（差于特征回归的 19pp） |
| 自测 × `k=8.58` | 是 | 15pp |
| 库常数基线（对照） | 是 | **11pp** |

决定性的一点：`w_hat / w_oracle` 中位 **0.0729**，而独立预测「horizon 减半 ⇒ `w` 只剩 11.66%」—— 两个数几乎重合。自测估的是 horizon 缩短了多少，不是误差分布。另外原始 `w_hat` 下 87/118 个 cell 仍 <50% 覆盖，只有 5/118 落在 70–90%。

**反直觉**：自测会破坏本来好的模型 —— NASA timesfm 不校准已 76.2%，自测把它「修正」到 48.8%（`w_hat=0.8` 把区间收窄了）。这个估计器没有「已经够宽就别动」的刹车。

## 4. §9.5-c 自测 + 事后 `k` 修正 —— 输给同等作弊预算的常数

乘一个全库拟合的 `k` 后偏离降到 15pp，看似成功。但一个**根本不用自测**的库常数基线，花同样的真值预算做到 11pp —— **净收益 −3.5pp，自测是负作用**。

**方法论教训（比结论本身更重要）**：「中位覆盖率回到 80%」不等于校准成功。判据必须两条同时满足：逐 cell 偏离分布 + 同等作弊预算下的常数基线。第一版我曾据此写成「这条路可行」。

## 5. §9.6 按曲率路由 / 加权集成 —— 没有可赚的钱

**证据**：逐 cell 完美选优（不可实现的天花板）相对最优单模型只改善 MIT −1.7%、NASA 0%、CALCE −20.1%。留一库路由 **6/6** 输给「两个候选里取优」。

**结论**：模型优劣是**库级**现象，不是 cell 级。可部署落点只剩下「拿到新库该用线性外推还是基础模型」这一条库级判据（用 `drop_ctx` / `slope_all`，只用上下文）。

## 6. 拉宽区间修「太窄」—— 横截面规律是相关，不是因果

9/15 个组合需要 10²–10³ 倍宽度（中位 394×），CRPS 中位涨 465%。关键反例：MIT chronos-bolt 拉宽 15×（把 `MPIW/MAE` 补到约 1.0）PICP 只到 43.0%，要到 80% 得 113×，CRPS 4.12 → 8.88。

**结论**：覆盖率高的模型不是「因为区间宽」，而是分布形状更接近真实误差。把形状错的分布等比放大，只会得到又宽又错的分布。反过来，「太宽」可以用单标量收好（4/15 组 `w_cov<1.5`，其中 3 组 CRPS 同时下降）。详见 `区间宽度校准.md`。

## 7. 跨库迁移 —— `w` 和校准头 `s` 都是数据分布属性

把 MIT 拟合的 `w`（2000×）搬到 NASA：CRPS 2.95 → **4041**。校准头 `s=1.65` 搬到 CALCE 是 **+1.2% 负迁移**。

**结论**：这两个量描述的是「这个库的误差有多大」，不是「这个模型有多大误差」。按库给常数可以，跨库搬不行。

## 8. 用 CRPS 当校准目标 —— 方向相反

11/15 个组合的 `w_crps` 撞到网格下界 `w→0`，即退化成中位数点预测。CRPS 是 proper scoring rule，但只在「在所有分布里挑」时以真实分布为最优；约束在「固定形状只改宽度」的一维族里，它奖励更窄。

**实践含义**：只报 CRPS 会系统性掩盖「区间太窄」这个本项目最主要的失败模式。

## 9. `knee_ratio` 当部署判据 —— 需要真值

拐点位置与上下文 `drop_ctx` 的库内相关确实强（ρ=−0.96 / −0.99），但 `knee_ratio` 本身要用真值算。改用 `drop_ctx`（只用上下文）后判据可用。

## 10. EOL 命中率当主要指标 —— 把失败记成满分

Lag-Llama 在 MIT 的 100% 命中，实为**早 197 个循环**就跌破 80%（RUL 相对误差 0.71）。常数 0% 也同样掩盖问题。已重设计为「RUL 相对误差 + 带符号过冲 + 未穿越裕度」三量，见 `EOL重设计.md`。

## 11. 干净克隆下 report 链的 4 个步骤需要原始数据（2026-10-22 新发现）

在无原始数据、无 `local_paths.py` 的干净克隆里跑 21 步 report 链：**exit 0，14 张图逐位一致**，5 个汇总 `.md` 内容一致（仅行尾差异）。但 `calibrate_width.py` / `online_proxy.py` / `diag_context_range.py` / `ablate_naive_linear.py` 四步因缺数据各 exit 1 —— 而 `run_matrix.sh` 的 `an()` 把所有失败都吞掉，链**恒返回 0**。

也就是说：报告链里任何一步真的崩了，从退出码上完全看不出来。修复已排入 §9.7（见下文前提表）。

## 12. 「14 张图 MD5 逐位一致」不是跨平台性质（2026-10-22 新发现）

§9.7 的 CI 首次运行暴露：14/14 张图的 MD5 在 Linux 上**全部改变**，
而依赖版本与本地完全一致（matplotlib 3.11.2 / numpy 2.5.4 /
pandas 3.0.6 / scipy 1.18.1 / sklearn 1.9.1），汇总链本身也全绿。

⇒ 差异来自**平台渲染/编码栈**（Windows 与 Linux 的 FreeType / zlib 不同），
不是版本问题、也不是数据问题。**这条性质只在同平台上成立。**

**修法**：CI 的图比对改成**像素级**（`scripts/check_figures.py --pixels`，
解码成数组后逐张比），文本产物仍要求一个字节都不变；
同平台的字节级复现留在作者机器上做（该脚本默认模式）。

## 共同点：为什么会反复失败

三条约束叠在一起，任何一条单独解决都没用：

1. **协议没有空间**：50/50 切分让「匹配 horizon 的自测」在数学上不存在（留给模型 0 点输入）；PICP 的「整段 horizon 都被盖住」定义让所需宽度对 horizon 长度极度敏感（减半只剩 11.7%）。
2. **库间差异大于库内差异**：同一个特征合并 ρ=−0.96、库内只有 −0.34；`w` 与 `s` 跨库即负迁移。凡是「按 cell 估一个量」的努力都会被库级差异主导。
3. **可估的都是协议常识，不可估的才是信息**：特征回归与自测最能预测的都是 `n_ctx`（= horizon 长度），而这是实验设计里已知的常数。
